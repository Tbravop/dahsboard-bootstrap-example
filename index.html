3. Esquema de la Base de Datos (`fact_tickets`)

Estructura de campos activa en memoria dentro del navegador:

  • ID_Ticket — PK único (ej. INC-2026-8401)
  • Fecha_Creacion — Datetime ISO de apertura
  • Fecha_Primera_Respuesta — Timestamp 1er contacto
  • Fecha_Resolucion — Timestamp de cierre
  • Prioridad — P1 - Crítica a P4 - Baja
  • Estado — Etapa actual en el flujo
  • Categoria — Clasificación técnica
  • Canal_Entrada — Portal, Chat, Email, Teléfono, API
  • Agente / Nivel_Soporte — Responsable y Tier
  • Tiempo_FRT_Min — Minutos hasta 1ª respuesta
  • Tiempo_MTTR_Horas — Horas netas de resolución
  • Resuelto_Primer_Contacto — Booleano FCR (1/0)
  • SLA_Cumplido — Booleano SLA (1/0)
  • CSAT — Puntuación 1 a 5 estrellas
